# 配置 GUI

[English](gui.md) | **简体中文**

`atvv-config` 是 `atvvd` 的 GTK4/libadwaita 配置客户端
（[ADR 0008](decisions/0008-gui-toolkit.md)）。它通过守护进程的
`GetConfig`/`SetConfig` API 编辑按键映射，并使用 `BeginCapture`/`RunAction`
进行测试模式。它从不写 `daemon.toml`、打开 evdev/uinput，或直接访问 BlueZ 或
PipeWire。

![ATVV 遥控器映射面板](gui.png)

## 安装与启动

GUI 是可选的 `atvv-gui` AUR 软件包；守护进程软件包不依赖 GTK。

```sh
git clone https://aur.archlinux.org/atvv-gui.git
cd atvv-gui
makepkg -si
systemctl --user enable --now atvvd
atvv-config
```

先安装 `atvv`；`atvv-gui` 依赖它。AUR 助手会解析该依赖。

守护进程未运行时，窗口会打开只读的“守护进程不可用”页面，并提供“重试”按钮。
守护进程保持无界面；`atvvctl` 仍然是可脚本化的接口。

## 语言

应用跟随桌面语言环境。英文是默认值和回退值；任何 `zh*` 语言环境都会选择简体
中文。应用内没有语言切换。更改桌面语言后，请重启 `atvv-config`。

## 映射面板

窗口是围绕当前设备矢量示意图（RC003 或 Chromecast 遥控器）的三列面板：

- 左侧卡片：电源、上、左、返回、主页、菜单；Chromecast 上还有 YouTube 和静音。
- 中间：遥控器示意图和语音键卡片。
- 右侧卡片：右、确定、下、音量加、音量减、电视；Chromecast 上还有 Netflix。
  Chromecast 没有菜单卡片，其 `tv` 槽位显示为 Input。

卡片集合跟随活动配置文件，因此切换设备时按键和示意图一起切换。

每张卡片显示三个手势槽位——**单击**、**双击**和**长按**——并以紧凑形式显示
解析后的操作（`Return`、`F13`、`Ctrl+Alt+V`、`Left click`、`Pointer up 1`、
`Command…`、`Start dictation` 或 `None`）。选中的卡片和槽位使用系统强调色。无操作的槽位会变暗；同一手势下
与其他卡片发送相同操作的卡片会以琥珀色描边。

点击槽位即可编辑该槽位。点击示意图上的按键会选择对应卡片并编辑其**单击**槽位；
示意图和卡片始终显示同一选择。窗口窄于面板时，面板横向滚动；顶栏和测试栏保持
可见。

示意图上的语音键（RC003 的麦克风键、Chromecast 的黑色 Google Assistant 键）
不是操作槽位。点击它，或示意图下方的**语音键**卡片，会打开录音键对话框。

## 顶栏

- **菜单**：*设备信息…*、*还原更改*、*关于 ATVV* 和 *退出*。
- **设备标签**：BlueZ 为活动遥控器报告的名称（用户可修改的别名，例如遥控器自带
  名称）和电量。没有 BlueZ 名称时回退到配置文件显示名和型号。点击它打开设备浮层：
  每个已知设备及其配置文件、布局和当前标记，以及*设备信息…*行。选择另一台设备会
  调用 `SelectDevice`；旧会话结束、释放 HID 独占，新设备在后台重连。文档有未保存
  更改时会用提示阻止切换；请先应用或还原。*设备信息*对话框显示名称、电池、遥控器
  地址以及设备信息服务事实（固件、硬件版本、软件版本、序列号、制造商、型号）。
  没有值的行会隐藏；断开连接时电量显示“上次值”。
- **布局标签**：活动设备当前布局的名称。点击它打开布局切换器，列出所有布局并可
  打开管理器。
- **副标题**：配置文件型号（`RC003`、`A3`）和会话状态。蓝牙地址在设备信息对话框中。
- **测试**、**还原**和**应用**。

切换设备会结束测试模式，重新加载活动设备的文档及其按设备布局；配置文件变化时
同步更新源名称（`atvv-miremote-rc003` 与 `atvv-google-chromecast`）。已知设备来自
`GetConfig`；GUI 不直接访问 BlueZ，配对仍由 `atvvctl pair` 完成。

## 布局

布局是一组命名的按键操作和手势时序。设备标签旁的布局标签显示当前布局，并打开
切换器。浮层列出每个布局以及当前标记和描述；**默认**带有“模板”标签。
**管理布局…**会打开管理器。

`默认`由设备配置文件合成，是模板。它可以编辑：点击槽位或热区会打开正常的编辑器，
并将更改暂存到工作副本。未保存横幅显示“默认布局有未保存的更改——应用后会另存为
新布局。”**应用**会打开**另存为布局**，而不是写入模板；名称、描述和暂存映射会
创建新的用户布局并设为当前布局。**还原**会丢弃暂存编辑并保持默认布局为当前布局。

用户布局可以在管理器中创建、重命名、复制、重置和删除。名称不区分大小写地唯一，
长度为 1–40 个字符；`Default` 以及预设 id `mpv`、`slides`、`omp` 为保留名称。
最多 32 个用户布局。点击管理器行会切换布局；行尾菜单提供复制、重命名、删除、重置
和“重置为预设…”。默认布局只提供复制，当前布局的删除不可用。重命名和**新建布局…**
使用内联的名称/描述表单。文档有未保存更改时，底栏显示**还原**和**应用**。

**从预设新建…**打开内置目录：mpv、演示（LibreOffice Impress 与 WPS 演示）和
omp，每项都显示验证版本。选择预设会预览活动设备的按键操作，并预填唯一名称。
**创建**会暂存一个非活动用户布局；当前布局保持不变，文档在**应用**前保持未保存
状态，之后可选择**使用**。用户布局菜单中的**重置为预设…**打开同一选择器，显示
受影响的布局名称，并在替换槽位前请求确认；布局名称和描述保持不变。默认布局不提供
重置，预设行不能编辑或删除。ATVV 不会检测前台应用或自动切换布局。

文档有未保存更改时会阻止切换：请先应用或还原。切换通过 `SetLayout` 实时应用映射
和手势时序，并保持测试模式开启，同时清除上次按键结果。切换失败会保留之前的布局
并显示错误。

全局设置（设备、增益、vinput 模式、录音键、exec 策略）不属于布局。示意图资源和
热区几何跟随当前设备配置文件，不随布局变化。所选布局持久化为
`active_layout`；默认模板从不写入 `daemon.toml`。

## 编辑映射

![操作编辑器](gui-editor.png)

1. 点击卡片槽位；若要点编辑示单击槽位，则点击示意图上的按键。**映射**对话框会
   针对该按键和手势打开，并显示该槽位是自定义映射、配置文件默认值还是未绑定。
2. 选择操作类型：
   - *无操作* 会吞掉按键（`none`）。
   - *单个按键* 发出一个按键，例如 `KEY_F13`。
   - *按键组合* 发出组合键，例如 `ctrl+alt+v`。
   - *运行命令* 通过守护进程运行 `exec:<command>`。
   - *听写* 启动、停止或切换 ATVV 麦克风。
   - *指针* 单击鼠标键（左键、右键、中键、侧键、扩展键、前进键、后退键或
     任务键），或按 1–255 个相对计数向上、向下、向左、向右移动指针。
3. 输入值、使用**学习按键**，或使用**选择…**从带名称和内核键名的可搜索列表中
   选择（包含输入后端支持的全部按键，显示友好名和内核键名）。选择器会插入所选
   按键；在组合键中只替换最后一个按键并保留修饰键。
   搜索会匹配内核名、本地化标签和英文标签，并忽略空格和分隔符（`print`、
   `printscreen`、`key_sysrq`），因此在任何语言环境下英文查询都能找到。截屏键是
   `KEY_SYSRQ`。学习时按住的修饰键会按 `ctrl`、`alt`、`shift`、`super` 的顺序
   成为组合键的一部分。
4. 点击**更新**。对话框关闭，面板显示新操作，顶栏的**应用**变为可用。当前布局为
   默认布局时，编辑会按“布局”一节所述暂存。

**指针**操作选择单击的鼠标键，或选择移动方向和单位数；单位是相对计数，桌面的
指针加速和速度设置仍然生效。用三个手势槽位区分距离，例如 `上` → 单击
`Pointer up 1`、双击 `Pointer up 10`、长按 `Pointer up 50`。只有已保存的映射
包含指针操作时，守护进程才创建 `atvv-virtual-pointer`。原始 `BTN_*` 值会被拒绝；
请使用指针编辑器。

**学习遥控器…**会启动守护进程的捕获模式；按下遥控器实体按键会将对话框切换到该
按键和手势。**重置**会恢复该槽位的配置文件默认值；**取消**会丢弃对话框中的编辑。

**应用**会校验完整文档，将其应用到运行中的守护进程，并原子地写入文件。默认布局
有暂存的槽位编辑时，应用会打开**另存为布局**；只更改布局列表的文档会就地写入。
无效输入会留在对话框中并显示内联错误，之前的映射保持活动。**还原**会重新加载
守护进程文档，丢弃未保存的编辑。

## 录音键

右上角的麦克风键是实体录音键（`KEY_F5`）。它被独占且固定：用于打开和关闭 ATVV
麦克风，不能作为普通操作按键。录音键对话框只编辑输出按键。

![录音键对话框](gui-recording-key.png)

- **输出按键**是按住录音键时发出的合成按键。默认是 `DICTATE`；使用**学习按键**
  捕获其他按键或组合键（例如 `F23`），或输入 `none` 禁用合成按键。
- **声明键…**列出运行中守护进程契约声明的录音键（`DICTATE`、`VOICECOMMAND`、
  `ASSISTANT`）以及**无（禁用合成按键）**。列表来自
  `StatusView.contract.recording_keys`，不是 GUI 中的副本。选择条目会填入输出
  字段；正常的**更新**和**应用**路径仍负责校验和保存。
- 对话框显示消费者名称映射（fcitx5-vinput 使用 `Dictate`、`VoiceCommand`、
  `Assistant`），并在 `vinput` 为 `dbus` 或 `off` 时给出警告，因为这些模式
  不会发出合成按键。消费者必须绑定相同的按键；提供方契约的 `active_key` 报告
  当前值。
- **更新**修改文档；顶栏的**应用**通过 `SetConfig` 持久化。**重置为 DICTATE**
  恢复默认值。实体 F5 和 ATVV 麦克风路径保持不变。

## 测试模式

在顶栏切换**测试**。捕获激活期间，守护进程上报逻辑按键事件；被按下的卡片槽位会
高亮，底部栏显示按键、手势和解析后的操作，**运行一次**变为可用。捕获会抑制自动
按键/组合键发出、`exec`、听写、合成语音触发以及语音会话的开始/停止，因此按下
确定或音量键不会激活焦点应用或改变系统音量。语音键报告为固定；测试模式下不会
启动麦克风。Shell 命令需要单独的确认对话框，默认响应为取消。

切换布局会保持测试模式开启，但会清除上次按键结果。关闭**测试**、点击横幅中的
**取消**，或 GUI 的 D-Bus 连接消失时，捕获结束。GUI
从不读取输入设备；evdev 独占、操作映射和捕获状态由守护进程负责。

## 脚本安全

除非 `allow_exec = true`，否则 `exec:` 处于禁用状态。在操作对话框中开启**允许
shell 命令**；开启需要明确确认。守护进程以当前用户身份运行命令，超时 5 秒，
标准输入输出已关闭，一次只运行一条命令，并在有效 uid 为 0 时拒绝运行。GUI 不
解释 shell 语法；启用前请审查命令。

## 键盘与无障碍

每个卡片槽位都是可聚焦的 `GtkButton`，带有无障碍名称和工具提示。Tab 顺序遵循
面板；Enter 或空格打开聚焦的槽位。操作对话框打开时捕获焦点，关闭后将其还给
槽位；Enter 触发**更新**，Escape 取消。焦点环、系统浅色/深色主题和系统强调色
由 libadwaita 提供；示意图资源本身与主题无关。

## 持久化

守护进程将活动设备、已知设备注册表、当前布局、所有用户布局和全局设置写入
`$XDG_CONFIG_HOME/atvv/daemon.toml`（默认 `~/.config/atvv/daemon.toml`）。同一
文档可通过 `atvvctl config get --json`、`atvv-mcp` 和守护进程的 D-Bus API 获取，
因此 GUI 不是第二份事实来源。活动设备及其布局在守护进程重启后仍然保留。

## 限制

- 一次只有一个活动设备配置文件；窗口显示守护进程上报的配置文件。设备浮层可在
  已知设备间切换并重新加载该设备的布局。面板遵循界面参考；其中的第二台遥控器
  只是示意。
- 不支持同时连接多个设备或按设备创建 PipeWire 源。
- 没有按应用分层的映射或自动快捷键发现。
- 应用内没有 ASR 或云协议；听写只驱动 ATVV 会话。
- GUI 是可选的。`atvvd`、`atvvctl`、`atvv-mcp` 以及 fcitx5-vinput 等消费者在
  没有 GUI 时仍可工作。
