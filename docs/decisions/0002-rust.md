# ADR 0002 — Rust for the daemon and protocol

## Status

Accepted, 2026-10-29.

## Context

The project needs a safe parser for untrusted BLE notifications, asynchronous
BlueZ/D-Bus work, a real-time audio path, and a small distribution footprint.
The two reference implementations (ATVVoice and sayall) are Rust; their protocol
and PipeWire code is MIT and can be learned from.

## Decision

Use Rust 2024 for the protocol library, daemon, and CLI. Keep the protocol
crate synchronous and I/O-free. Use tokio only for the future daemon's BLE,
D-Bus, and control paths; keep PipeWire on a dedicated OS thread and a bounded
single-producer/single-consumer queue.

## Consequences

- The protocol crate has no BlueZ/PipeWire dependencies and is cheap to test.
- The daemon can use `bluer`, `pipewire-rs`, `evdev`, and `zbus` without
  language-boundary wrappers.
- GUI is not part of the core decision; a future GUI is a separate process over
  D-Bus.
